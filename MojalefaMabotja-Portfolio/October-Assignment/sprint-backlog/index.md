# PowerShare — Sprint Backlog

## 1. Project Overview

**Project Name:** PowerShare
**Project Type:** Portable Battery Rental Platform
**Development Approach:** Agile
**Team Size:** 3 members
**Communication Tool:** WhatsApp
**Task Management Tool:** Trello
**Source Code Collaboration:** GitHub

## 2. Introduction

The sprint backlog identifies the work selected for a specific development sprint. It breaks larger product requirements into manageable tasks that team members can implement, test and review.

For PowerShare, sprint tasks may include developing user authentication, displaying battery information, implementing rental bookings, integrating payment functionality, managing administrative features and improving the user interface.

## 3. Sprint Goal

**Proposed sprint goal:**

To develop and improve the core PowerShare functionality so that customers can interact with the platform, explore available battery rental options and submit rental requests, while administrators can manage relevant platform activities.

## 6. Sprint Monitoring

Sprint progress can be monitored through the team's task management records.

Trello can help the team identify which tasks are awaiting work, in progress or completed. The team should update task statuses as work progresses and discuss any problems that may affect delivery.

A useful sprint review should consider:

* Which tasks were completed?
* Which tasks remain outstanding?
* What challenges affected progress?
* Were any requirements changed?
* What should the team improve during the next sprint?

## 7. Testing and Quality Assurance

Testing should be performed on the functionality developed during the sprint.

For PowerShare, relevant checks may include:

1. Confirming that valid registration and login details are handled correctly.
2. Checking that battery information is displayed appropriately.
3. Verifying that rental booking requests are processed correctly.
4. Checking the feedback provided by the payment process.
5. Confirming that booking updates are displayed appropriately.
6. Checking that administrative functions behave as intended.
7. Testing navigation controls and identifying interface problems.

## 8. Challenges and Improvements

Potential areas for review include integration between frontend and backend functionality, handling errors, ensuring that navigation works consistently and coordinating tasks among team members.

The team should document the challenges that actually occurred during the sprint and explain how they were addressed.

Any unresolved issues should be carried forward into the appropriate backlog rather than recorded as successfully resolved.

## 9. Sprint Review and Retrospective

At the end of the sprint, the team should review the work produced and compare it with the sprint goal.

The retrospective should consider what went well, what did not go well and which changes could improve future collaboration.

## 10. Conclusion

The sprint backlog provides a framework for organising development activities into manageable tasks. It supports task allocation, progress monitoring, testing and team collaboration.
