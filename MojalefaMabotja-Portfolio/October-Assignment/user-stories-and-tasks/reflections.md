# Reflection: User Stories and Tasks

## Situation

During the development of PowerShare, a portable power station rental platform, I needed to identify the features required by customers and administrators. The system needed to support functions such as customer registration, login, browsing available batteries, making rental bookings, and managing bookings.

## Task

My responsibility as the Full-Stack Developer was to break down the required features into clear user stories and manageable development tasks. Each user story needed to represent a user requirement, with three tasks outlining the work needed to implement the feature.

## Action

I organised the features into user stories based on the needs of customers and administrators. I divided each story into three tasks, covering activities such as designing interfaces, implementing functionality, and validating information. For example, the customer registration story included designing the registration screen, implementing the registration form, and validating the required user information. I also considered how the frontend and backend needed to work together to support the platform's functionality.

## Result

This process helped me understand how user stories connect software development activities to user needs. Breaking features into three tasks made the work easier to organise and track. It also improved my understanding of how Agile supports incremental development and teamwork. In future projects, I would improve this process by agreeing on acceptance criteria with the team before development and ensuring that completed tasks are supported by evidence, such as screenshots, tests, and GitHub commits.
